Most automation demos stop at “done.” Arcade Ops asks two more questions: who decided, and what proves the result?

This is Project Aurora, a release due tomorrow. A browser operator can use seven native Web M C P actions to inspect the real workspace — not scrape the screen. One validation is blocked. Production changes and outside contact are forbidden.

The operator prepares a bounded mission. The plan appears here, with dependencies, a hard cost cap, and four evidence checks. Then it delegates one persisted run to the release worker.

Arcade Ops stops at the decision that actually matters: stage with documented residual risk, or postpone. The software explains both outcomes, but it cannot choose for me. I select staged release.

The same signed run resumes. The worker produces the release summary and rollback plan, without touching production.

Now the proof. Four checks pass. I accept this exact evidence pack. Relay issues a signed certificate and verifies it.

The operator delegated. I decided. Arcade Ops kept the evidence.
